# 密封多单位拍卖与保证金清算（合成实现）

纯合成账户与虚构拍卖规则，**不连接任何真实金融服务**：无加密密封、真实支付、税费或信用授信。金额一律为**整数分**，账户/场次/标的均为虚构。

## 规则

- 每场卖出 `K` 个同质单位（1–10），每买家最多一个有效 bid；bid 含正整数数量、整数分单价、稳定 `bid_id`。
- 截止前可**完整替换**（更高 `revision` + 新冻结凭据）或**撤销**；截止后不可改标。
- 排序：单价降序、`bid_id` 升序，分配 `min(qty, 剩余)` 直到 `K` 用尽，允许最后一标部分成交。输入顺序不参与并列判定。
- 统一成交价 = **所有获配单位中的最低投标价**；无人获配则无成交价。
- 每买家订单额 = 获配数量 × 统一价；未成交单位不收费。
- 上限：最多 5 买家/场、每场 10 单位、本部署总计 3 场。

## 联合密封征集（成套标，并列于旧合同之外）

虚构展会一次租出**不同型号的若干时段**：一次联合征集声明若干资源（≤8 种、每种 1–3 单位），买家提交一份**互斥方案菜单**（≤4 案，每案 = 一组资源 + 整案整数报价），≤20 买家。

- **成套不可拆**：方案要么整案成交要么不成交；同一买家最多赢一案（XOR）。
- **按被选方案各自整案报价收款**（pay-as-bid），不是统一价。
- 菜单有稳定 `menu_id`；截止前可**换单**（revision+1 + 新担保，旧担保同一事务释放）或**撤标**；截止后结果只读复读。
- **担保**：托管仓签发一张绑定 `(征集, 买家, 菜单, 修订号)` 的担保（`contract_kind=PACKAGE_TENDER` 的普通 hold），金额 ≥ 菜单最高可能单笔付款（最高方案价）。一张担保覆盖整组互斥方案。已在其他场/他种合同冻结的现金不能再用于担保。
- 托管仓担保台提供：**预审菜单**（结构 + 所需担保额 + 可用余额是否够）、**正式冻结担保**、**查看签证覆盖哪些方案**。
- **截止时只冻结核过保证金的菜单**（担保被提前释放的菜单记入 excluded），随后求**总报价最高的合法获配**；并列时按入选方案稳定标号升序表取**字典序最小**。
- 结算：赢家按整案价实扣（上限为担保额，余量释放），输家与被排除菜单的担保全额释放；仓库操作带确定性 request id，回执丢失只接着清原成交物。
- 双版本操作通过 `holds.contract_kind`（`UNIT_AUCTION` / `PACKAGE_TENDER`）辨认，互相不能用错凭据。

### 规格实例（A/B 各一单位）

- 甲：`{A,B}@9` XOR `{A}@7`；乙：`{B}@5`；丙：`{A}@4`。
- 甲担保 9 → **甲得 A（付 7）+ 乙得 B（付 5）= 12**。
- 甲截止前换单为唯一 `{A,B}@9` → 与 `丙A+乙B` 同价 9；本实例标号下 `("C-A","Y-B") < ("J-AB",)`，**丙乙中标**。
- 甲可冻结余额仅 6 → 两项菜单（最高单笔 9）拿不到担保，**丙乙仍以 9 成交**。

## 保证金口径

每个买家恒满足：

```
累计入金 = 可用 + 有效冻结 + 已扣款
```

- 冻结资金按 hold 绑定到**单一拍卖/征集**，不能同时支持另一场投标。
- 结标后按**冻结结果**消费：获配者按价扣款并释放余量（扣款额不超过该 hold 冻结额），未获配者全额释放；hold 置为 `CONSUMED`/`RELEASED`，重复结算不再扣款。
- 数据库唯一索引 `ux_charge_once(auction_id, hold_id) WHERE kind='CHARGE'` 作为最后一道防线。
- 冻结余额在 `BEGIN IMMEDIATE` 事务内派生，两个连接争最后一分钱只有一个能成功。

## 一致性设计

| 关注点 | 实现 |
| --- | --- |
| 投标凭据核验 | 拍卖/征集端在投标/冻结时直接读 `holds` 行，核对合同种类、买家、场次、金额、`ACTIVE` 状态（担保还核对菜单+修订号绑定），绝不信任调用者自填“已冻结” |
| 撤标/换价原子性 | 撤销标记、新凭据安装、旧凭据释放处于**同一事务**，不存在旧款已释放但旧标仍可结标的窗口；换单失败旧菜单与旧担保同时原样保留 |
| 结标结果不可变 | 截止时一次性计算并写入 `settlements.allocations_json` / `tender_settlements.result_json`；重开、重试、付款失败均复读同一份 |
| 响应丢失 | 每个写操作带 `request_id`，响应持久化在 `receipts`；相同请求重放返回已提交结果，不同请求复用 id 报冲突；重传换单不会产生第二张可花凭证 |
| 结算续跑 | 每个 hold 的仓库操作使用确定性 `request_id`（`settle:<auction>:<bid>` / `settle:<tender>:<menu>`），崩溃后任意调用者可按实际状态续做，不会双扣 |
| 待决状态 | `settlements.status` / `tender_settlements.status` = `FROZEN → CLEARING → CLEARED`，部分结算可见且可继续 |

## 目录

```
sealed_auction/
  db.py          SQLite schema、BEGIN IMMEDIATE 事务、holds 合同种类列迁移
  core.py        错误、UTC、幂等回执
  margin.py      保证金仓：入金/冻结/解冻/上限扣款/余额/凭据核验（按合同种类）
  auction.py     旧式拍卖服务：投标/修订/撤销/冻结结标/结算/复读/解释
  solver.py      菜单校验 + 联合征集最优获配（资源用量向量 DP，标号字典序破同）
  guarantee.py   托管仓担保台：预审菜单/冻结担保/签证覆盖查询
  tender.py      联合征集服务：报菜单/换单/撤标/截止冻结/结算/复读/解释
  clearing.py    跨模块编排、对账单（两种合同）
  reconcile.py   仅从原始事件独立重算账户、获配与最优解
examples/run_demo.py         旧式拍卖复跑入口
examples/run_tender_demo.py  联合征集三场景复跑入口
tests/test_scenarios.py        16 个旧式场景测试
tests/test_tender_scenarios.py 18 个联合征集场景测试
```

## 复跑

```bash
python3 -m unittest tests.test_scenarios tests.test_tender_scenarios -v
python3 -m examples.run_demo                        # 旧式拍卖（临时库）
python3 -m examples.run_tender_demo                 # 联合征集（临时库）
python3 -m examples.run_tender_demo --db t.sqlite3  # 持久库；多次运行自动命名空间隔离
```

`run_tender_demo` 逐步打印：预审与担保冻结 → 三买家菜单 → 截止最优（甲A+乙B=12）→ 按案实扣与余量释放 → 换单后同价按标号破同（丙乙=9）→ 余额 6 拿不到担保（丙乙=9）→ 重复结算不双扣 → 独立对账。

## 已验证场景

`python3 -m unittest tests.test_scenarios` 覆盖：

- 并列截断由 `bid_id` 决定，而非输入顺序；
- 部分成交 + 统一价低于部分中标者报价，订单按统一价计；
- 撤标/换价原子替换冻结；
- 冻结不足、伪造凭据、跨买家/跨场次凭据、已释放凭据被拒；
- 同一 hold 不能支撑另一场投标；
- 重复结算、并发结算、扣款响应丢失后续跑均只扣一次；
- 截止后投标/撤销/修订被拒；扣款失败不改变冻结榜单；
- 两连接争最后余额仅一个成功；
- 空场无成交价；
- 限额与“每买家一个有效 bid”；
- 对账能从原始事件发现被删除的扣款。

`python3 -m unittest tests.test_tender_scenarios` 覆盖：

- 规格实例三种结局（12 / 换单后标号破同 9 / 余额 6 拒保后 9）；
- 互斥案整案成交、每买家最多一案、按案实扣（非统一价）、余量与输家担保释放；
- 换单原子性：失败时旧菜单与旧担保同时原样保留；事务中途崩溃整体回滚；重传换单只回放回执，不产生第二张可花凭证；
- 担保绑定（征集/买家/菜单/修订号）与合同种类不可混用；他场已冻结现金不能再担保；
- 预审、签证覆盖查询、担保低于菜单最高单笔付款被拒；
- 截止前释放担保的菜单被排除，其余照常成交；
- 截止后菜单不可改、结果复读一致、结算断点续跑只扣一次；
- 两真实连接争最后余额仅一个成功；
- 限额（8 资源/3 单位/20 买家/4 案/未知资源/超供/非整数价/标号重复）；
- 求解器与暴力枚举在随机小实例上逐一比对（含标号破同）；
- 20 买家 × 4 案 × 8 资源 × 3 单位：多买家抢同一稀缺型号与各取不同型号混合，对账通过；
- 对账能从原始事件发现被删除的联合拍扣款。
